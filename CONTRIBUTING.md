# Contributing to ShaderX

Start with the [contributor guide](docs/contributing.md) for JDK and Android SDK setup, sample commands, the source layout, and tests.

- Report a reproducible bug with the [bug report form](https://github.com/Debanshu777/ShaderX/issues/new?template=bug_report.yml).
- Propose an effect or API improvement with the [feature request form](https://github.com/Debanshu777/ShaderX/issues/new?template=feature_request.yml).
- For small documentation fixes, send a focused pull request directly.
- Discuss substantial API changes in an issue before implementing them.

Describe what changed, why, and how you checked it. Include the platform, library version, and a screenshot or recording for visual changes. Keep unrelated dependency upgrades out of the change.

For every codebase change, update both `README.md` and the affected Markdown guides in `docs/` in the same PR. This includes tests, internal refactors, tooling, and workflows. Follow [AGENTS.md](AGENTS.md) for the change-to-guide map and required documentation checks. Prose-only and media-only changes do not need companion edits.

Use respectful, constructive communication. Do not include tokens, signing keys, private images, or personal data in issues or pull requests.
